# Owner WMS same-round handoff

This is a local integration candidate for the private WMS Apps Script with the current fast WMS query. Its manifest stays owner-only and retains the existing OAuth scopes. The sender uses the project's already-approved UrlFetch capability. No new web app, trigger, Gmail scope, or broader Drive scope is used.

- The owner project patch captures the two validated Osan responses from the same existing fetchAll call. The native Sheet's own reconciliation and commit rules still apply. The sender consumes the pair once, after the Sheet lease is released. Network failures are recorded separately and do not change the Sheet outcome or retry either provider request.
- The transmitted fields support round/center/date, dispatch identity, route, stop count, sale amount and delivery identity checks. Phone, driver names, customer names, addresses and source credentials are excluded. The approved reader flag stays off until staff inspect how the captured records project without address evidence.
- Before live activation, review the current owner project version and approve the exact recipient and WMS fields. Use the existing secure configuration channels for the receiver's approval flag and the site-specific derived WMS credential in the owner project's script properties. The raw scheduler signing secret stays with the scheduler. The server only accepts a signed exact-body digest for that site, path, date and Osan center, with a 512 KiB cap and a 5-second body deadline. A single publication may be in progress.
- The receiver's handoff approval is separate from reading or publishing official rounds. The existing archive write approvals and private credentials must also be present. Stage review should confirm a real same-round write and independent readback before deciding whether to enable the official reader. Legacy XLSX and FreshOn releases continue through their original independent index.
- Existing owner GAS clock handlers read MIS, and the Render night and morning WMS path continues to read FreshOn MIS. For an approved nightly capture, set the optional nightly property in the existing scoped handoff settings. It defaults to off. Only the existing owner Fast clock can invoke the hook. The registered clock UID and the corresponding completed MIS receipt must match.
- The hook runs after the clock releases the Sheet lease. In the 21:10 to 22:10 KST window it can read the next delivery day for Osan. One existing WMS login supplies one paired plan and detail batch. A persisted attempt marker prevents a second query after a failure, uncertain acknowledgement or restart. The regular clock keeps its original receipt and the ordinary MIS archive keeps its own write path.
- After reviewing the current owner project, enable the nightly capture only for the approved receiver and existing WMS read account. Confirm the existing clock actually fires within the required window. The first real capture must pass both reconcile checks, complete a verified encrypted write and be independently read back before enabling display. Older official counts cannot supplement a different MIS round.

- The morning MIS job retains its no-duplicate behavior when a verified release already exists. A separately approved newer MIS correction takes precedence as a whole release and has no verified official stop count. If the signed latest MIS revision cannot be read, the reader does not display older official stops as a fallback.
- An owner Fast WMS correction for the current delivery day automatically hands over its verified pair after the existing Sheet publication. That handoff uses the already-read pair and adds no source request or new trigger. The routine morning owner clock does not read the official WMS pair, so a new official morning capture requires its own authorized source check.


owner-project.patch applies to the protected project's reviewed HEAD archive. It adds capture and after-release hooks for the existing manual and clock paths. Do not apply or deploy it against a different Apps Script version without first revalidating those hooks.
